# Wave 4, feature #1: Virtualized geometry on Trifactor (design contract)

Status: DESIGN, frozen for the implementing agent. 2026-10-11. Scope: make the Trifactor cluster path the default geometry path where the device can run it; GPU-driven two-pass hierarchical-Z occlusion culling of clusters; per-cluster LOD selection by screen-space error with a provably consistent (crack-free) cut; a compute-culled indirect-draw fallback so Vulkan and older GPUs work; fixed-LOD BLAS for ray tracing; shadow and existing-culler interaction. Not in scope (v1): software rasterisation of micro-polygons, a visibility buffer, cluster page streaming, skinned or translucent virtualized meshes, tessellation or displacement. Parent plan: `docs/plans/UE_FEATURE_PARITY_PLAN.md` row 1. Earlier plan (partly stale, kept for history): `docs/VIRTUALIZED_GEOMETRY.md`.

## 0. Decisions in one screen

1. **No new module and no new third-party code.** The cook half stays in `Aver.Trifactor` (CPU only, no RHI, `modules/trifactor/CMakeLists.txt`). The GPU half is a new component of `Aver.Render.Voxi` (`ClusterRenderer`, own files), because the only pixel shaders that shade a scene correctly (G-buffer, RT shadows, reflections, denoiser inputs) are Voxi's `PSMainVoxi` family and the cluster path must feed *them*, not a second copy. Hosts (`Sandbox`, `Runtime`) only submit instances. `Trifactor` and `Occlusion` stay optional behind `#if AVER_MODULE_TRIFACTOR` / `#if AVER_MODULE_OCCLUSION`; Voxi lists both under `optionalDependsOn`.
2. **Today's GPU cluster path is not a base to default on; it is replaced.** It is editor-only (`sandbox/src/SandboxRender.cpp:1050-1195`), D3D12-only (`SandboxApp.cpp:624-655`), one dispatch per entity instance, tests every cluster of every LOD level flat (129,666 for `pine_tree_01`, `ClusterAdapt.hpp:283`), draws one material per mesh, uses a private pixel shader (`sandbox/shaders/cluster_material.hlsl`) that writes no G-buffer, no velocity and no ray-traced lighting, and has no occlusion culling. The packaged game has no cluster path at all (`Runtime` uses Trifactor only for shadow proxies and collision, `GameContent.cpp:419-445, 1056-1075`).
3. **The cut test changes from per-cluster spheres to shared group spheres.** The current local test (`draw iff ownError < B and parentError >= B`, each at the cluster's own sphere) can disagree between a child and its parent and open holes; `ClusterSelect.hpp:96-104` already admits "a real gap". The fix needs no new on-disk data for chunk-v3 files: derive enclosing LOD spheres at load from the existing `groupNodes` and `ownerGroupId` / `fallbackAncestorId` (section 3.1).
4. **Material-pure clusters** (cook change, MLET chunk v4, `kBuilderVersion` 3). Today clusters straddle submeshes (`modules/trifactor/README.md`: `MeshletStart/Count` written 0,0). A mesh with more than one material and no material-pure clusters is refused by the virtualized path and draws through the existing discrete-LOD path. Single-material meshes work on existing cooked data.
5. **GPU-driven end to end, indirect.** Instance table -> instance cull (LOD level range, frustum, HiZ) -> cluster cull (LOD cut, frustum, cone, HiZ) -> bin by batch -> raster, run twice per frame (main pass against last frame's HiZ, post pass re-tests the survivors of the "occluded last frame" set against a HiZ built from this frame's main pass). The RHI has **no indirect draw or dispatch** today (`grep -i indirect modules/rhi/include` is empty; neither backend creates a command signature or calls `vkCmd*Indirect`), so section 3.9 adds it, additively.
6. **Two raster back ends, one shading contract.** Mesh-shader (AS+MS, SM 6.5) and compute-culled vertex-pull indirect draw (VS, SM 6.0). Both emit the existing `VSOut` into the unchanged `PSMainVoxi` variants, so material graphs, G-buffer, RT, blended exclusion, fog and AverSR/NRD2 keep working. `Auto` picks mesh shaders where the pipeline pair is proven to create, else compute. Vulkan starts on the compute back end (the mesh-shader scene variants are refused there per commit `449140a2`; see risk R4).
7. **Ray tracing sees one fixed LOD per mesh** (`rtProxy`, coarsest level with world error <= `rtErrorCm`), built as a normal `MeshHandle` that shares the LOD-0 vertex buffer, exactly as the shadow/GI `depthProxy` is built today. No per-ray LOD (design-around, section 2).
8. **Default ON** (`Quality::High` on `RENDER.GEOMETRY`, 1.0 px budget, the same budget as today's `lodErrorThresholdPx_ = 1.0`) when Voxi is attached, compute shaders and indirect execution exist, and the mesh has virtualization data; otherwise the existing discrete LOD (`--lod-select`) path runs unchanged.
9. **Delete what this replaces**, in the last phase: `--lod-per-cluster` CPU path (`clusterCutCache_`, 1.9 s/frame on Electric Dreams per `ClusterAdapt.hpp:279-285`), the `AVER_MS_CLUSTER` block of `shared_prelude.hlsl:903-1096`, `sandbox/src/ClusterMaterialShader.hpp`, `sandbox/shaders/cluster_material.hlsl`, `SandboxApp::ensureLodMeshPipeline`, `meshClusterGpu_`, and `RHI dispatchMeshClusters`. `--lod-mesh-shader` / `--no-lod-mesh-shader` stay as aliases.

## 3. Design

### 3.1 Cook and load: what the clusters carry

**Group LOD spheres (load-time, no format change for chunk v3).** Let G be a group node (`ClusterGroupNode`, `ClusterBuilder.hpp:178`): its member clusters are one level finer, its output clusters one level coarser (`ownClusterRange`). For every cluster c define:

- `selfGroup(c)` = `ownerGroupId(c)`: the group that produced c (none for level 0).
- `parentGroup(c)` = `ownerGroupId(fallbackAncestorId(c))`: the group of which c is a member (none for roots). `fallbackAncestorId` is an output of exactly that group (`ClusterBuilder.hpp:136-154`).
- `lodSphere(G)`: **enclosing, bottom-up**: the smallest sphere (Ritter or iterative `mergeSphere`, the helper already used for group spheres) enclosing every member cluster's own bounding sphere **and** `lodSphere` of the group that produced each member. Level 1 groups enclose only member bounds.
- `lodError(G)` = `ownError` of any output cluster of G (identical across a group; `computeClusterErrorBounds` guarantees it, `ClusterBuilder.hpp:369-393`), in cm.

Per cluster the GPU record then holds `selfSphere = lodSphere(selfGroup)`, `selfErr = lodError(selfGroup)` (0 for level 0), `parSphere = lodSphere(parentGroup)`, `parErr = lodError(parentGroup)` (`FLT_MAX` and an unused sphere for roots). Every cluster in a decision (a group's members, and that group's outputs) therefore evaluates **the same sphere and error pair**, see 3.4. `trifactor::deriveLodSpheres(const OcMeshData&) -> LodSpheres` does this in O(groups) at mesh load; `validateLodSpheres` checks enclosure numerically (distance + inner radius <= outer radius + eps) and `selfErr <= parErr`.

**Material-pure clusters (cook).** `buildClusters` runs `meshopt_buildMeshlets` per submesh range (`OcMeshData::submeshes`, `OcMesh.hpp:22-29`), not over the merged index buffer; `buildLodHierarchy` forms groups only among clusters of one material slot; borders between material regions are group borders and stay locked, so material seams never simplify (accepted cost; very patchy meshes keep more triangles at coarse levels, reported by `RelodTool`). New per-meshlet field `u16 materialSlot` (index into `OcMeshData::materialSlots`). MLET chunk **v4**: v3 layout + `u32 MaterialSlot` appended (52 B), readers keep v1-v3 (`FORMAT_SPECS.md:246-247` pattern: version-gated stride; append section 5.7 text, do not rewrite). `kBuilderVersion` -> 3 (`ClusterBuilder.hpp:48`), so `RelodTool --write` reports old ladders as stale. `SubmeshRange.MeshletStart/MeshletCount` become real per-submesh ranges for LOD 0 (closes the README gap).

**Runtime eligibility** (`trifactor::virtualizable(const OcMeshData&, why)`): has meshlets and `coarserLods`, <= 32 levels, not skinned, every meshlet's slot < `materialSlots.size()`, and either chunk v4 or exactly one distinct slot. Failing meshes use discrete LOD with one `AVER_INFO` naming the reason once.

### 3.2 GPU data (the pool)

One `ClusterPool` per `ClusterRenderer`, sub-allocated, grow-by-doubling with copy, freed per mesh on unload. Static buffers are `BufferKind::Default` (GPU-local), filled through `IResourceFactory::bufferStager()` or an Upload buffer + `copyBuffer` (today's code leaves them in Upload memory, read over PCIe: `SandboxAssets.cpp:240-247`).

```
// 80 B. All floats cm, mesh-local space. Mirrored byte for byte in HLSL; static_asserts on both sides.
struct ClusterCull {           // StructuredBuffer<ClusterCull> gCl
  float3 center;  float radius;          // 0   cluster bounds (frustum, HiZ)
  float3 coneApex; uint  coneAxisCutoff; // 16  axis snorm8x3 | cutoff snorm8 (cutoff = +1 or <= -1 => never cull, as today)
  float4 selfSphere;                     // 32  xyz centre, w radius  (lodSphere(selfGroup))
  float4 parSphere;                      // 48
  float  selfErr;  float parErr;         // 64  cm; 0 / FLT_MAX at the ends
  uint   meta;                           // 72  triCount(8) | level(6) | materialPart(10)   (triCount <= 124 fits 8 bits)
  uint   desc;                           // 76  index into gDesc
};
struct ClusterDesc { uint vertexOffset, triangleOffset, vertexCount, triangleCount; };   // 16 B, = GpuMeshletDesc today
// gVerts: uint per slot, GLOBAL vertex index into the MESH's own vertex buffer (not a copy of vertices).
// gTris : uint per triangle, a | b<<8 | c<<16 (local indices), same as buildMeshClusterGpuData.
struct MeshRecord { uint clusterBase, clusterCount, levelCount, partCount; float maxLodSphereExcess; uint pad[3];
                    LevelRec level[32]; };             // LevelRec 32 B: firstCluster, count, minSelfErr, maxSelfErr, minParErr, maxParErr, pad[2]
```
Per-level min/max are the existing `MeshClusterLevelBounds` (`ClusterAdapt.hpp:296`), recomputed over the new group-sphere errors. Clusters of a mesh are stored level-ascending, so a level is a contiguous id range; `maxLodSphereExcess` = max over clusters of how far a `lodSphere` extends beyond the mesh bound (for `dMin`, 3.4).

Vertex data is **not duplicated**: the mesh's existing vertex buffer (`rhi::MeshVertex`, 32 B, `RHI.hpp:48`) is bound per batch exactly as `dispatchMeshClusters` binds it today. Pool cost per cluster = 80 + 16 + (vertex slots x 4) + (triangles x 4). Budget `geom.poolBudgetMiB` (default 1024); a mesh that would exceed it is not registered (discrete LOD, logged). Per-mesh and total MiB are logged `[GEOM] mesh '<rel>' ...`.

**Instances.** Per frame, `StructuredBuffer<InstanceGpu>` (128 B), ring of 3 (`kInFlight`, same reason as `OcclusionCuller.cpp:101-125`):
```
struct InstanceGpu { float4 w0,w1,w2; float4 p0,p1,p2;   // 3x4 world, 3x4 previous-frame world (row-vector convention, as everywhere)
                     float4 sphere;                       // world bounding sphere of the whole instance, xyz centre, w radius
                     uint meshRec, batch, flags, pad; }; // flags: bit0 movable, bit1 hiddenFromOwner(not drawn), bit2 noHiz
```
Cap `geom.maxInstances` (default 131072); overflow instances fall back to the discrete path and are counted. `prev` = `World` matrix of the previous frame for this entity (the host already tracks `prevObjectToWorld` for RT movers; `PlayMobility`/`scene::World` previous transform; if unknown use current, which makes HiZ conservative only for motion, never wrong because the post pass re-tests).

**Batches.** A batch is `(meshRec, part, material binding, PerObject constants)`: the host's resolved per-part draw (`planEntityDraws`, `SceneSubmission.hpp:127-167`) supplies the material binding set and constants (32-dword PerObject block + material block bytes). Equal tuples merge; `kMaxBatches = 4096` per frame, the rest fall back. `part` selects clusters by `materialPart` (the `materialSlot` of the cluster mapped to the part index of `GameContent::partsFor`). The PerObject world matrix field is unused by the cluster front end (world comes from `InstanceGpu`); everything else the pixel shader reads from PerObject (base colour, metallic/roughness, shading-model tail) is batch-constant by construction.

### 3.4 LOD selection: exact rules and why the cut is crack-free

Per view: `projScale = viewportHeightPx / (2 tan(fovY/2))` over the **scene render target height after render-scale** (`trifactor::projScale`, `ClusterSelect.hpp:145`; under AverSR/TAAU the budget is in internal-resolution pixels, which is what is rasterised). Budget `B = max(geom.errorPx, kMinClusterBudgetPx)` (`ClusterAdapt.hpp:238`).

```
dist(S)  = max(length(S.xyz - eye) - S.w, 0)           // to the sphere surface, world space; S transformed by the instance world, w scaled by maxAxisScale
px(E,S)  = dist(S) <= 1e-3 ? 1e30 : E * scale * projScale / dist(S)       // E in cm, scale = maxAxisScale(world)
draw(c)  = px(selfErr, selfSphere) < B  &&  px(parErr, parSphere) >= B
```
(Same comparators as `inLocalCut`; root `parErr = FLT_MAX` always passes the second term, level 0 `selfErr = 0` always the first. `maxAxisScale` replaces today's x-axis-only `worldScale`, `SandboxRender.cpp:1062`; with non-uniform scale it can only refine.)

**Why the cut covers every surface exactly once.** Take a path of ancestors c0 (level 0) -> c1 -> ... -> ck (root) via group membership. The pair (sphere, error) attached to the edge "c_i is a member of group H, producing c_{i+1}" is `(lodSphere(H), lodError(H))`, and it is the *same* pair for every member of H and for every output of H: it is c_i's `parSphere/parErr` and c_{i+1}'s `selfSphere/selfErr`. Define `p_H = px(lodError(H), lodSphere(H))`. Then c_i draws iff `p_{G(i-1)} < B <= p_{G(i)}` where G(i) is the group c_i is a member of, with `p_{G(-1)} = 0` and `p_{G(k)} = inf`. If the sequence `p_G` along the path is **non-decreasing**, exactly one index satisfies this, so exactly one ancestor-or-self of every leaf draws. Non-decreasing needs (a) `lodError` non-decreasing child group -> parent group (validated at cook: `validateClusterErrorBounds`, `ClusterBuilder.hpp:404`), and (b) `dist(lodSphere(parent group)) <= dist(lodSphere(child group))` for every camera, which holds when the parent sphere **encloses** the child sphere (nearest-surface distance of an enclosing sphere is never larger) - exactly what the bottom-up `lodSphere` construction in 3.1 guarantees and `validateLodSpheres` checks. The existing per-cluster-sphere rule has neither guarantee (`ClusterSelect.hpp:96-104`), so it can emit zero (hole) or two (overdraw) clusters on a path. A test enumerates the property (section 5).

**Instance-level level range** (pass 1) generalises `provablySingleLevelCut` (`ClusterAdapt.hpp:312-365`): with `dc = |eye - instance.sphere.xyz|`, `R = instance.sphere.w`, `X = mesh.maxLodSphereExcess * scale`: `dMin = max(0, dc - R - X)`, `dMax = dc + R + X`. A level L can contribute only if NOT (`level[L].minSelfErr*scale*projScale >= B*dMax` [too coarse everywhere]) and NOT (`level[L].maxParErr*scale*projScale < B*dMin` [parent always good enough]). Levels that survive form the range `[lo, hi]` (not assumed contiguous; the range is their hull, correctness is per-cluster anyway). If `dMin` cannot be bounded away from 0 the range is all levels. Output-sensitivity: far instances touch only coarse levels, so tested clusters ~ proportional to drawn clusters (target <= 3x). A hierarchical group-node traversal is the next step if measurement shows pass 2 dominating near large instances (open question 3).

**Budget pressure.** If `gVisA`, `gRetest` or the triangle cap would overflow (`geom.maxClusters` default 524288 visible clusters, `geom.maxTriangles` default 2,000,000 for the VS-pull list), the counter saturates, excess entries are dropped, `[GEOM] overflow` is logged once, and next frame's `B *= 1.25` (decays by 0.95 per frame back to the setting). Dropping is a visible hole for one frame; the alternative of unbounded buffers is worse.

### 3.5 Hierarchical-Z occlusion

Reuses `Aver.Occlusion`'s mechanics; changes there (owned by this feature):

- Extract **`HizPyramid`** from `OcclusionCullerImpl`: `ensureSized(res, w, h, samples)`, `build(ctx, sceneDepth)` (seed with MSAA `max`, then reduce chain, the existing kernels `occlusion_seed.hlsl`, `occlusion_reduce.hlsl`), `texture()`, `mipCount()`, `size()`. `OcclusionCullerImpl` owns one and behaves byte-identically (its tests and `--occlusion-cull` unchanged). `ClusterRenderer` owns two (`cur`, `hist`) and swaps.
- New shader include **`occlusion_hiz.hlsli`** (deployed through `aver_deploy_shaders`, loaded with `rhi::shaderFile`): `bool hizOccluded(Texture2D<float> pyr, float4x4 viewProj, float4 vpRect, uint2 pyrSize, uint mips, float3 aabbLo, float3 aabbHi)` = the corner projection, mip selection (`largest > 1 texel -> ceil(log2)`), four-corner `Load` compare of `occlusion_test.hlsl:60-118`, **with two changes**: any corner with `clip.w <= 1e-5` returns "not occluded"; the compared depth is `nearestZ - hizEps` with `hizEps = 4 / 2^24`, and the rectangle is grown by 1 pixel before mip selection (TAA jitter: the pyramid holds jittered depth, tests use the unjittered projection). Depth convention near = 0, far = 1 (not reversed), pyramid stores the **max** (farthest). Input box = world AABB of the cluster sphere. `OcclusionMath.hpp` gets the matching CPU function, tested against the same synthetic pyramids.
- **Previous-frame test without depth reprojection.** Pass 1/2 test the cluster's bounds transformed by the **previous** instance world (`InstanceGpu.p*`) and the **previous** viewProj and viewport rect against `gHizPrev`. That answers "was this cluster hidden where it was last frame", needs no warped depth, and handles moving instances.
- **Why correct.** A cluster that tests hidden against last frame's pyramid is not dropped: it is queued and re-tested in the post pass against the pyramid of *this* frame's main pass, with *this* frame's transforms. The post pass can only draw more, never less. A cluster wrongly hidden by a stale pyramid is therefore drawn one pass later in the same frame; HiZ error costs overdraw, never popping. The final pyramid (step 8) is built from everything drawn, so history stays honest.
- **History validity.** `hist` is invalid on: first frame, scene target resize or viewport-rect change, render-scale or sample-count change (`ensureSized` returns changed), `geom.freeze` toggle, `ClusterRenderer::resetHistory()` (called by hosts on level load, teleport, camera cut, FOV change > 5 degrees, `AverSR` mode switch, device reset). On an invalid frame pass 1/2 skip the HiZ term (everything LOD/frustum/cone-visible draws in the main pass) and step 6 has nothing to do.
- **Viewport sub-rect** (editor docked panels) uses the same `gViewport` rect mapping as `occlusion_test.hlsl:46-58`; the editor's `occlusionViewportRect` is the single source.
- **Translucent / blended** draws never write depth into the pyramid (they are not in the opaque pass). Alpha-masked (cutout) materials write only surviving pixels, so the pyramid is exact for them.
- **Coexistence with the entity-level culler** (`--occlusion-cull`): virtualized instances are not offered to `IOcclusionCuller::testBatch`; they self-cull. The CPU culler stays for non-virtualized entities and keeps its `waitIdle` behaviour untouched. If the entity culler is on, its own pyramid is a separate object; the two do not share storage (cost: one extra R32F pyramid per `HizPyramid`, ~ 1.3x the scene depth size).

### 3.6 Raster back ends

Common: pixel shader = existing `PSMainVoxi` compiled four ways (opaque, `AVER_GBUFFER`, `AVER_RT`, both), selected by the same logic as `VoxiRenderer::scenePipeline` (`:7394-7412`); blended is excluded (such instances take the discrete path as today, `SandboxRender.cpp:1036-1049` comment). Cull mode `None` as the existing scene pipelines (`:8006`). Depth `Less` write. Wireframe view bypasses the cluster path.

**Mesh-shader back end** (`AVER_GEOM_MS`, SM 6.5). AS: group of `kClusterAmplificationGroupSize` (32) threads reads 32 consecutive `gVisSorted` entries of its batch (`SV_GroupID.x*32 + gtid < batchCount`), fills a payload of 32 `{inst, cluster}`, `DispatchMesh(n,1,1)`. MS: one group per payload entry (64 threads, <= 64 vertices, <= 124 triangles, `SetMeshOutputCounts` first, as `MSClusterMain`), vertices from the mesh VB at the global index in `gVerts`, `world` from `gInst[inst]`, emits `VSOut {pos,nrmWS,wpos,uv}` (`shared_prelude.hlsl:764`) with `averTransformNormal`. Dispatched with `dispatchMeshClustersIndirect(mesh, gArgs, off)`.

**Compute / vertex-pull back end** (`AVER_GEOM_VS`, SM 6.0, no mesh shaders). After binning, pass `geom expand` (indirect, 1 group of 64 per visible entry, entries read from `gVisA` not sorted) writes 8 B per visible triangle `{entryIdx, localTri}` to `gTriList` at `gBatchBase[b] + atomicAdd(cursor[b], triCount)` (`gBatchBase` from the scan over `gBatchTri`). The batch is drawn by `drawClustersIndirect(mesh, gArgs, off)` = `{vertexCount = 3*triCount, 1, 0, 0}`; the VS reads `SV_VertexID -> triangle = vid/3, corner = vid%3 -> entry -> {inst, cluster} -> gDesc/gTris/gVerts -> mesh VB`, same transform and `VSOut`. Cost is one extra pass and ~16 MB at the 2 M triangle cap, no IA, no index buffer, no per-cluster draw. This is the portable floor: SM 6.0 D3D12, Vulkan without mesh shaders, `CapsOverride no-ms`.

**Selection (`geom.backend`)**: `Auto` = mesh if `caps.meshShaderTier > 0 && shaderModel >= 65 && dxcAvailable` **and** the AS+MS+`PSMainVoxi` pipeline creation succeeded on this backend (probed once, like `ensureLodMeshPipeline`'s latch, re-probed on a material-graph revision change); else compute; else (`!computeShaders || !caps.indirect`) the whole feature reports unavailable and discrete LOD runs. `mesh` / `compute` force one (forced mesh with no support logs and uses compute). Render-pipeline hazards already known: the vertex/index root SRV must be set for every mesh pipeline even if unread (`D3D12Device.cpp:9235-9245` comment); on Vulkan the mesh-geometry set binds only to `MESH_BIT_EXT` today (`VulkanDevice.cpp:1355-1365`) and must also be visible to `VERTEX_BIT` for vertex pull.

**Why not a visibility buffer or software raster in v1.** The visibility buffer needs per-pixel material evaluation from a triangle id; this engine's raster path is not bindless (`RHIResources.hpp:3`; `createBindlessTextureTable` is the ray-hit-shading exception), every material is a root binding set, and `PSMainVoxi` fuses material, GI, RT and G-buffer output. A visibility pass would force re-plumbing all of that and is where the patent exposure is least understood (section 2). Software raster pays off below ~1 px triangles; with a 1 px budget a hardware 2x2-quad penalty of up to 4x on the finest clusters is the measurable cost (section 8) and the number that decides whether a v2 is justified.

### 3.7 Shading, materials, G-buffer, quality interplay

- **Velocity** in the G-buffer is camera-only reprojection (`voxi.hlsl:1077, 1112` use `gPrevViewProj` with the current world position), so the front end needs no previous-position output; instances that move get the same limitation as every ordinary draw today.
- **Material graphs**: cluster pipelines are rebuilt on `pbr::materialGraphs().revision()` and `rhi::shaderFileRevision()` changes, in the same `prePass` hook that rebuilds scene pipelines (`VoxiRenderer.cpp:1176-1195`). The material define string is produced by the same `pbr::materialShaderDefines(gi.srvCount, kMaterialSamplerSlot, layeredBsdf_)` call as `createScenePipelines`; the materials feature may change that function but not its call contract (section 6 shared rules).
- **Binding layout**: cluster pipelines use `giLayout()` (the Voxi layout, table 0 = GI + ... , table 1 = material) plus pool SRVs placed in the **second** declarable table's unused registers or, if the layout cannot hold them, a third `bindingSet` at the top of table 0 (implementer decides after reading `giLayout()`; the pool set is static per `ClusterRenderer` and rebuilt only on pool growth). This replaces the table-0 merge hack that made the cluster path D3D12-only (`D3D12Device.cpp` `nullFill` comment cited at `ClusterMaterialShader.hpp:30`).
- **Depth prepass** (`--depth-prepass`, default off): cluster instances are excluded from the prepass walk as today (`SandboxRender.cpp:362-368`); they draw with the normal `Less` pipeline afterwards, so the prepassed meshes' later `LessEqual/no-write` draws are unaffected.
- **MSAA / TAA / render scale**: pyramid built per sample count (MSAA `max` over samples); TAA needs MSAA 1 (`OcProject.hpp:96`) so the common packaged case is single-sample; render scale changes the pyramid size (history reset).
- **Ray-driven primary visibility** (`rtRenderMode` primary rays, `RenderSettingsResolver.hpp`): the raster scene is suppressed, so `recordFrame` is a no-op (`IRenderFeature::suppressesScene()`); primary rays hit the fixed-LOD BLAS (3.8). Visual consequence: in that mode silhouettes are limited by `rtErrorCm`, documented in the settings tooltip.

### 3.8 Shadows, GI, ray tracing, the old culler

- **Shadow / GI / voxelise (v1)**: unchanged mechanism and cost. Every virtualized instance still calls `VoxiRenderer::submit(proxyMesh, world, material, ...)` from the host (the "colourAlreadyDrawn" direct route, `GameRender.hpp:230`), where `proxyMesh = depthProxy` (error <= 20 cm), instanced per cascade (`VoxiRenderer.cpp:4937-4973`). The cluster renderer never draws into the cascade atlas in v1. Caveat: this keeps one CPU `submit` per instance (`kMaxDraws = 65536`, `VoxiRenderer.cpp:1076`); a million-instance scene needs the static-batch feature (#12), out of scope.
- **Ray tracing (v1)**: new `rtProxy` per mesh: coarsest level with `levelWorldErrorCm <= geom.rtErrorCm` (ladder: Low 4, Medium 2, High 1, Epic 0.5 cm), created as a `MeshHandle` sharing LOD-0's vertex buffer (`createMeshSharingVertices`, as `SandboxAssets.cpp:158-170`), only if it has fewer triangles than LOD 0, else LOD 0. `Voxi::Draw` gains `rtMesh`; `submit()` resolves it through a second proxy callback (`setMeshProxies(depthFn, rtFn, user)`, keeping `setDepthProxy` as a thin wrapper); the TLAS/BLAS code at `VoxiRenderer.cpp:1740-1760` and `rtInstanceMesh_` use `d.rtMesh` (falls back to `d.mesh`). This also cuts BLAS VRAM for virtualized meshes (today's BLAS is the full LOD 0 triangle count; `aver-vram` compaction already applies to whatever is built). Non-virtualized meshes keep `rtMesh == mesh` (no behaviour change).
- **Cascade clusters (phase 4, off by default `geom.shadowClusters`)**: the cull kernels are view-generic (`ViewParams` array, up to 5 views: main + 4 cascades; shadow views pass `B` = cascade texel size converted to px, no HiZ, frustum = cascade box), writing a per-view `gVisA` region; depth-only AS/MS or VS-pull pipeline (no PS, as `shadowPso_`, `VoxiRenderer.cpp:7803`). Gate it behind a measured win: today's proxy path costs `Voxi shadow` ms in `--gpu-timing`; enable only if cluster cascades beat it on foliage-heavy scenes. Virtual shadow maps (feature #3) will own large-scale shadows and consume this same view-generic interface.
- **Interaction with GI voxelisation**: unchanged (uses `depthMesh`).
- **Entity-level occlusion** (`SandboxApp` `occluder_`): see 3.5.

**Shared-file rules with the other wave-4 features**
- Many-light (Voxi lighting / unified lights): owns `voxi.hlsl` lighting, the scene-light table and `VoxiRenderer.cpp` lighting passes. Geometry does not edit `PSMainVoxi` or any lighting function; it only *compiles* it with the same defines. If the lights agent adds a binding/register to `giLayout()`, `ClusterRenderer::createPipelines` must use `giLayout()` unmodified so it follows automatically (this is why 3.7 forbids a private layout). Pool SRV registers are allocated *after* `declaredSrvCount(giLayout())`.
- Materials (`render.pbr`, `MaterialGraph`, `.ocmat`, editor material panels): owns `pbr::materialShaderDefines/Prelude`; contract: the call used by `createScenePipelines` is the one cluster pipelines reuse; a material feature change that adds defines/registers must update `createScenePipelines` and `ClusterRenderer::createPipelines` in the same commit (one grep: `materialShaderDefines(`). Geometry never edits `modules/render.pbr/**`.
- Texture streaming (`modules/assets`, RHI texture residency, `render.pbr` bindings): geometry's RHI edits are the 3.9 block only; texture streaming's RHI edits go in their own delimited block and must not reorder `ResourceState` (append only; `AccelerationStructure` stays last: the geometry enum value is inserted before it, so whichever lands second rebases mechanically). Batches bind material sets through `setDrawBinding`, so residency changes that rewrite a material binding set are transparent to the cluster path provided the set handle stays stable or the host passes the current handle each frame (it does).
- Both backends' device files (`D3D12Device.cpp`, `VulkanDevice.cpp`) are touched by several features: edit only inside the delimited blocks, never reformat, commit separately, rebase before push.
- `OcProject.*`, `EditorConsole.hpp`, `SandboxSettings.cpp`, `SandboxMain.cpp`: append-only additions in a clearly marked group.

## 8. Performance budget and measurement

Targets (to be verified; no numbers below are measurements):
- Culling total (spans 1-3 + 6-7 bin) <= 0.6 ms at 1440p for 20k instances / 1.5 M tested clusters on a mid-range DXR GPU. Arithmetic: 1.5 M x 80 B = 120 MB of cluster reads ~ 0.3-0.4 ms at 300-400 GB/s; the rest is append traffic.
- HiZ builds <= 0.15 ms each at 1440p (R32F pyramid: seed + ~11 reduce dispatches; the existing `HZB build` span is the baseline to quote).
- Raster not slower than the legacy `--lod-mesh-shader` on the same scene at the same pixel budget, and >= 1.5x faster than `--no-virtual-geometry` on the dense-foliage scene (Electric Dreams `pine_tree_01`-class); the legacy path's CPU cost (1.9 s/frame in per-cluster CPU mode, ~1.1 s on stat frames) is gone, CPU cost per instance <= 1 us in `submit`.
- Memory: pool cost per section 3.2; instance ring 3 x 16 MiB at 131072 instances; HiZ 2 pyramids; VS-pull list 16 MiB at the cap. Report totals in `[GEOM]`.
- Known cost to quantify: 2x2 quad inefficiency for ~1 px triangles at the finest levels; report `trianglesDrawn / pixels` and the High-vs-Low (1.0 vs 2.0 px) frame time difference; this is the figure that justifies or kills a software-raster v2.

## 9. Risks and open questions for the owner

R1 **Patent exposure unresolved.** No Epic patent found, but the search tooling could not query Google Patents directly; Microsoft US 11,004,255 (two-pass depth pyramid, stereo-framed claims) is the closest live neighbour. Decision needed: commission a counsel read of claims 1/13/18 before shipping HiZ two-pass by default. A hard fallback exists: ship with `geom.hiz` default off (single pass, no retest) and everything else unchanged.
R2 **Re-cook required for multi-material meshes.** Until a mesh is re-cooked (builder v3), it stays on discrete LOD. Plan a bulk `RelodTool --write` pass over project content; asset sources are irreplaceable, the tool never touches its input (`FORMAT_SPECS.md:247`).
R3 **Mesh seams never simplify** (locked material borders): meshes with thousands of tiny material patches keep many triangles at coarse levels. Measure on NewSponza and Jungle assets; escape hatch is mixed-material clusters with per-triangle material ids (v2).
R4 **Vulkan mesh-shader + `PSMainVoxi` pairing.** Commit `449140a2` states Voxi's mesh-shader variants are refused on Vulkan; I did not locate the refusal site (suspects: `descriptorLayout` for mesh layouts and the 144-byte push-constant floor, `VulkanDevice.cpp:1355`). The design assumes compute (VS-pull) is the Vulkan default until the mesh pair is proven; the implementer must confirm VS + `PSMainVoxi` pipelines already create on Vulkan (they do for `VSMain`) and that `meshGeometryBinding` is feasible there. Also not available on Vulkan today: SM 6.6 features (not needed here), bindless raster textures (not needed), `shaderInt64Atomics` (not used).
R5 **Pool vs duplicate vertices**: v1 reads the mesh's own 32 B vertices through a per-batch binding to avoid duplicating VRAM; the cost is one indirect call per batch (<= 4096) and the RHI `meshGeometryBinding` plumbing. If batch counts hurt (hundreds of tiny meshes), a pooled compact vertex stream (20 B/vertex) would allow one draw per material at +62% vertex VRAM; decide after P2 measurements.
R6 **Flat per-instance level-range cull** still tests every cluster of the surviving levels. If a scene has many near, very large instances, pass 2 can dominate; next step is group-node traversal with a work queue (needs persistent-thread-style ping-pong lists). Trigger: `clustersTested / trianglesDrawn*124 > 4` sustained.
R7 **Per-instance CPU submit remains** (`kMaxDraws = 65536`, shadows/TLAS). Million-instance scenes need the packed static batch feature (#12); this design leaves a seam (`ClusterInstanceIn` batch submit).
R8 **Shadows still use a 20 cm proxy** in v1, so near cascades can show proxy silhouettes on small casters (as today). `geom.shadowClusters` addresses it only if it wins on cost; VSM (#3) is the long-term owner.
R9 **Ray-driven primary mode shows the `rtProxy`** silhouette; per-distance BLAS LOD buckets are possible (two or three BLAS per mesh) but cost VRAM; open question whether `Epic` quality should build a second, finer BLAS.
R10 **TAA/jitter and HiZ tolerance** (1 px rect growth, `hizEps`) are a conservative guess; the zero-diff A/B in section 5 is the gate that tunes them. If the diff is not zero in motion, widen before shipping.
R11 **Skinned, blended, vertex-animated** meshes are excluded (discrete path); foliage wind animation in vertex shaders (if any exists) would desync cluster bounds from drawn geometry: confirm no material graph vertex offset is applied to cluster draws, or add bounds inflation per material flag.
R12 **Latent issue noticed**: `occlusion_test.hlsl` near-plane straddle (section 1). Not fixed here; fixing it changes the existing `--occlusion-cull` image.
